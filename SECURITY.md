# Security policy

## Supported release

Security and safety-boundary reports are accepted for the latest public release.

## Private reporting

Use **Security → Report a vulnerability** in the GitHub repository. Include the affected path or record identifier, the concern, and the minimum detail needed to reproduce it. Do not post secrets, personal data, or operational biological detail in a public issue.

Public issues are appropriate for ordinary schema, documentation, and non-sensitive label-quality problems.
